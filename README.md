# Synchronous FIFO Design and Verification

A parameterized, single-clock synchronous FIFO implemented in synthesizable Verilog-2005, with a SystemVerilog testbench and reproducible PowerShell workflows. This project is a synchronous FIFO; it does not implement asynchronous FIFO clock-domain crossing.

## Design summary
## Architecture Overview

See the [FIFO architecture block diagram](docs/ARCHITECTURE.md) for the design structure, control logic, and data flow.
Default configuration is 8-bit data and 16 entries. `DATA_WIDTH` and `DEPTH` are parameters; the documented contract includes depth one and non-power-of-two depths. The design uses bounded circular read/write pointers, an occupancy counter, registered read data, and per-edge overflow/underflow flags.

Reset is active-low and synchronous. Requests are evaluated using occupancy immediately before each rising edge. A read at empty is rejected; a write at empty is accepted even when read is also requested. At full, simultaneous read and write return the old oldest word and accept the replacement write. `dout` holds its previous value when no read is accepted.

See [PROJECT_SPEC.md](PROJECT_SPEC.md) for the complete interface and edge contract, [VERIFICATION_PLAN.md](VERIFICATION_PLAN.md) for test methodology and limitations, and [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for the design walkthrough.

## Repository contents

- `rtl/` — synthesizable FIFO RTL.
- `tb/` — SystemVerilog scoreboard testbench and netlist timescale helper.
- `scripts/` — tool discovery, lint, simulation, regression, waveform, synthesis, and summary scripts.
- `docs/` — architecture and waveform interpretation.
- `constraints/` — scope note; no target timing constraints or physical design are supplied.
- `results/` and `reports/` — selected historical evidence only. Generated run directories are intentionally excluded.

## Tools

The scripts use PowerShell, Icarus Verilog/VVP, Verilator, and Yosys. GTKWave is optional for viewing a waveform generated by the testbench. Graphviz is optional. Install and configure these tools separately; this repository does not bundle them. Tool locations can be supplied through `OSS_CAD_SUITE`, `YOSYSHQ_ROOT`, or the individual `*_EXE` environment variables used by `scripts/common.ps1`, or tools can be available on `PATH`.

## Reproducing checks

From the repository root in PowerShell, after installing the required tools:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\check_tools.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\run_lint.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\run_simulations.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\run_regression.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\generate_waveforms.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\run_synthesis.ps1
```

`run_all.ps1` runs the complete workflow. It generates outputs beneath `results/`, `reports/generated/`, and `waveforms/generated/`; these generated outputs are ignored by `.gitignore`.

## Saved validation evidence

The selected summaries describe a **historical saved run completed on 20 October 2026**, not a fresh validation of this repository copy. The original handoff reports 73 passing simulations and 881,951 checked rising edges across RTL suite, regression, synthesized-netlist tests, and a waveform run. It also records lint and generic Yosys synthesis for nine configurations. The checked-cycle count and run scope are documented in [`results/SAVED_EVIDENCE.md`](results/SAVED_EVIDENCE.md); RTL/testbench hashes are provided in [`results/saved/source_hashes.json`](results/saved/source_hashes.json).

The testbench uses procedural scoreboard checks and coverage counters. No SVA, formal verification, exhaustive proof, FPGA implementation, or ASIC physical design is claimed. Yosys results are technology-independent generic synthesis results; they are not timing closure, physical area, or power measurements. No asynchronous FIFO or Gray-coded CDC logic is implemented.
